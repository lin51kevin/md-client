# MarkLite++ 挑战目标 · 个人汇报总结

> 汇报日期：2026-07-09 | 项目：MarkLite++ v0.11.3
> 汇报维度：挑战设定 · 达成水平 · 尝试过程 · 客观障碍 · 学习沉淀

***

## （1）我设定的挑战是什么？

我给自己定的挑战是：**独立从零打造一款生产级的桌面 Markdown 编辑器**，并且不做"玩具 Demo"，而是要在体验上直接对标 Typora、Obsidian、VS Code 这些成熟商业 / 头部开源产品。

具体拆成三个硬指标：

* **技术挑战**：采用当时较新的技术栈（Tauri 2 + React 19 + CodeMirror 6），验证"Rust 原生外壳 + Web 前端"能否既轻量又完整地承载复杂编辑器。

* **功能挑战**：实现真正的 WYSIWYG 所见即所得编辑（而非简单的双栏预览），并支持多标签、多光标、跨文件搜索、多格式导出这类"重功能"。

* **工程挑战**：把它当成一个长期维护的产品来做——要有插件生态、权限安全、i18n、自动更新、测试覆盖，而不只是能跑起来。

***

## （2）实际达成的水平是什么？

坦白说，**达成度超出了最初预期**，从 v0.2.0 一路迭代到 v0.11.3，形成了完整可交付的产品：

* ✅ **核心体验对标成功**：双引擎编辑（CodeMirror 源码 + Milkdown WYSIWYG 双向同步）、**AST 精准块级编辑带完整 undo/redo**——这一点在对比表里连 Typora / Obsidian 都做不到，是真正的差异化亮点。

* ✅ **功能完整度到位**：多标签 + 拖拽、多光标、跨文件搜索、Wiki-Link、命令面板、五种导出格式（PDF/DOCX/HTML/EPUB/PNG）全部落地。

* ✅ **工程体系成熟**：建立了带**权限沙箱**的插件系统 + 18+ 官方插件、中 / 英 / 日 i18n、自动更新、外部文件变更检测、80% 测试覆盖、ESLint/Prettier、跨平台（Win/macOS/Linux）。

**没完全达成的部分**（诚实评估）：移动端和 Web 版没做，主题 / 插件生态的**数量**远不及 Obsidian、VS Code 那种社区规模——这更多是生态积累时间问题，而非架构能力问题。

***

## （3）我做了什么尝试？

* **快速验证 + 小步快跑**：两个月发了 20+ 个版本，几乎每 1-2 天一个发布，用高频迭代快速试错，而不是憋大招。

* **敢于推翻重来**：v0.9.0 时果断用 Milkdown Crepe **替换掉 react-markdown**，为了真正的 WYSIWYG 体验重构了整条预览管线——这是最关键的一次技术豪赌。

* **架构持续演进**：从最初的 props-drilling → 引入 Zustand；从巨型 `App.tsx` → 拆成 `AppProviders` / `AppShell` + 多个聚合 hook；从内置功能 → **微内核 + 插件化**（v0.11.0 把 Mermaid/Vim/Terminal 等抽成官方插件）。

* **TDD 贯穿始终**：用 F0xx 功能编号追踪，坚持先写测试、code review 修复，逐步把覆盖率提到 80%。

* **性能专项攻坚**：v0.10.0 集中做懒加载、Web Worker 卸载大文档、React.memo、Rust release profile（`opt-level = "z"` + LTO + strip）压体积。

***

## （4）遇到了什么客观障碍？

* **新技术栈的坑**：Tauri 2 + React 19 都比较新，遇到不少边界问题——WebView2 黑屏、Ubuntu 22.04 GLIBC 兼容、Windows 下 lib 命名冲突、esbuild 二进制安装失败等。

* **WYSIWYG 的本质难度**：所见即所得 + 源码双向同步是编辑器领域公认的难点，光标可见性、表格单元格编辑、Milkdown 初始化误标 dirty、ProseMirror focus 丢失等问题反复出现。

* **国际化与编码陷阱**：多字节字符 / emoji 的偏移量必须按 UTF-16 计算，非 UTF-8 文件（GBK/GB18030）需自动探测编码。

* **安全债务**：插件系统天然带来攻击面——路径穿越、Shell 命令注入、插件清单被篡改，都需要专门用白名单、权限沙箱、字段消毒去堵。

* **跨平台一致性**：主题适配、CRLF/LF 换行、原生对话框、右键菜单集成，每个平台都有各自的差异要抹平。

***

## （5）我学到了什么？有哪些沉淀与积累？

**认知层面：**

* **"先跑通、再重构"是对的**：不追求一步到位的完美架构，而是让功能先落地、随规模增长持续演进，反而走得更快更稳。

* **敢推翻是一种能力**：v0.9.0 换掉预览引擎的决定证明，及时止损、拥抱正确方案，比在错误路径上打补丁更值。

* **安全和 i18n 要趁早**：这些如果留到后期补，成本会指数级上升——把它们当成一等公民从设计阶段就纳入。

**能力 / 资产沉淀：**

* 掌握了一套**完整的 Tauri 桌面应用工程范式**：前后端职责划分、IPC 解耦、Rust 侧 I/O 与导出、release 体积优化。

* 沉淀了**可复用的插件系统 + 权限沙箱模型**，以及 18+ 官方插件这套可扩展资产。

* 建立了**规范化的研发流程**：语义化版本 + Keep a Changelog、TDD、code review、ESLint/Prettier、80% 覆盖率、CI。

* 积累了 CodeMirror 6 / Milkdown / ProseMirror 的深度实战经验，以及跨平台编码、字符偏移、性能优化等一批"踩过的坑"。

**一句话总结**：这次挑战不仅交付了一款对标头部产品的编辑器，更重要的是把"如何独立地、可持续地做一个真正的产品"这件事跑通了一遍——从技术选型、架构演进到工程规范，形成了可迁移到下一个项目的完整方法论。
